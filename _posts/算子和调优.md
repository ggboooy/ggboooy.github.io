# 算子优化
## 注意事项
写算子的时候一定要记得三个层级：launch的时候block小内存密集型（比如128 256），block大计算密集型（512 1024）。（从Occupancy考虑）。

考虑三个层级：block是调度层，luanch发射多少个block。kernel里面的整体是block，调度单位是warp，执行单位是thread。warp是SIMT 32线程一起执行，warp内部一般用shfl_sync_down(oxffffffff,val,16)一般前面不用加同步。
__syncthreads()是block内部所有都同步。
## Occupancy
warp占用率，首先sm如果block资源满足的话(thread,warp,block,register,smem)会尽量调度连续blockid到自己身上。一个sm最多64个warp活跃 4个warp scheduler在每个周期给warp发射指令，所以在内存密集算子occupancy高
是好事情，可以延迟隐藏，Occupancy占用率是 waprs / 64。但是计算密集型算子的话可以接受Occupancy低，因为会影响L2 cache，register，所以Occupancy低一点。。
gmem的内存延迟是400cycles，每条指令的执行周期是4，所以要100warp才能延迟隐藏。


## reduction算子
最原始的版本：
```
// V0: 朴素的树形规约（步长从小到大）
__global__ void reduce_v0(float* input, float* output, int n) {
    extern __shared__ float smem[];

    int tid = threadIdx.x;
    int gid = blockIdx.x * blockDim.x + threadIdx.x;

    // 将全局内存数据加载到共享内存
    smem[tid] = (gid < n) ? input[gid] : 0.0f;
    __syncthreads();

    // 树形规约：步长从 1 开始逐步翻倍
    for (int step = 1; step < blockDim.x; step *= 2) {
        if (tid % (2 * step) == 0) {
            smem[tid] += smem[tid + step];
        }
        __syncthreads();
    }

    // 每个 Block 的结果写回全局内存
    if (tid == 0) {
        output[blockIdx.x] = smem[0];
    }
}

```

```
// V2: 步长从大到小，同时消除 Warp Divergence 与 Bank Conflict
__global__ void reduce_v2(float* input, float* output, int n) {
    extern __shared__ float smem[];

    int tid = threadIdx.x;
    int gid = blockIdx.x * blockDim.x + threadIdx.x;

    smem[tid] = (gid < n) ? input[gid] : 0.0f;
    __syncthreads();

    // 步长从 blockDim.x/2 开始，每轮减半
    for (unsigned int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            smem[tid] += smem[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) {
        output[blockIdx.x] = smem[0];
    }
}
```
2.这时候其实干活的线程太少了，比如256个线程进入for循环里面，只有128个线程在干活。这时候的选择是一开始让256线程处理两个数，这样就能多干一点活。

3.最后一个warp是32个线程，这时候就不用同步了，直接全部处理。

4.for循环展开，可以减少for循环跳转，减少死代码。

5.可以先warp内部规约全部shfl_down_sync寄存器直接交换，然后不同warp规约的数据再用smem来同步，减少smem的读取。

6.减少load指令，把数组强制转换为float4，一个warp读取4个float(也就是4 * 32)，这里的写法的float4 data;data.x+data.y+data.z+data.w（刚好cacheline是128KB，不过和这里没啥关系）。

```
// V7: float4 向量化加载 + Grid Stride Loop + Warp Shuffle
__global__ void reduce_v7(float* input, float* output, int n) {
    int tid  = threadIdx.x;
    int lane = tid % 32;
    int wid  = tid / 32;

    // float4 加载：每线程每次处理 4 个 float
    float4* input4 = reinterpret_cast<float4*>(input);
    int n4 = n / 4;  // float4 的元素数量

    float val = 0.0f;

    // Grid Stride Loop：每个线程以 gridDim.x * blockDim.x 为步长迭代
    for (int idx = blockIdx.x * blockDim.x + tid;
         idx < n4;
         idx += gridDim.x * blockDim.x)
    {
        float4 data = input4[idx];
        val += data.x + data.y + data.z + data.w;
    }

    // 处理 n 不是 4 的倍数时的尾部元素
    int tail_start = n4 * 4;
    for (int idx = tail_start + blockIdx.x * blockDim.x + tid;
         idx < n;
         idx += gridDim.x * blockDim.x)
    {
        val += input[idx];
    }

    // Warp 内规约
    for (int offset = 16; offset > 0; offset >>= 1) {
        val += __shfl_down_sync(0xffffffff, val, offset);
    }

    __shared__ float warp_results[32];
    if (lane == 0) warp_results[wid] = val;
    __syncthreads();

    int num_warps = blockDim.x / 32;
    if (wid == 0) {
        val = (lane < num_warps) ? warp_results[lane] : 0.0f;
        for (int offset = 16; offset > 0; offset >>= 1) {
            val += __shfl_down_sync(0xffffffff, val, offset);
        }
    }

    if (tid == 0) output[blockIdx.x] = val;
}

调用方式：
// 固定 Grid 大小为 SM 数 × 4（最大化 GPU 利用率）
int num_sms;
cudaDeviceGetAttribute(&num_sms, cudaDevAttrMultiProcessorCount, 0);
int grid_size  = num_sms * 4;   // 432 for A100
int block_size = 256;

reduce_v7<<<grid_size, block_size>>>(d_input, d_partial, n);
```
