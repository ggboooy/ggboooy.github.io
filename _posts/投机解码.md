# 投机解码思路

# eagle

单独一个draft小模型，让小模型decode多猜几个，大模型一次性全verify验证了。eagle-3可能会用到大模型前面某些token的hidden_state来作为输入提升正确率。

eagle有两个结论：

1.decode换成prefill，让访存瓶颈变成部分算力瓶颈

2.Speculative Sampling。

https://chatgpt.com/share/6a8fb250-06c8-83ec-bd0e-c11d31b4e3e9

主要是考虑两个。首先是从p_d samples出了一条AR路径，但是我们真正要想的是p_t的sample路径。怎么做到等价呢？

考虑两种情况：P(accept_x)和P(reject_x)就是对从p_d的概率下成功sample到了x这个token和拒绝某个token后采样到了正确token x的概率。

当前token采样概率是P_d，我们真正的概率是P_t，所有接受概率是p_t / p_d。也就是说如果random() < min(p_t / p_d,1)当前token就等价于P(accept_x) = min(p_t,p_d)

P(reject_x)的概率就是剩下的P_t -  min(p_t,p_d)。这部分概率只有p_d <= p_t才不为0.所以当拒绝采样发生的时候，这部分概率为norm(max(p_t-p_d))。这里的意思是vocab token级别的相减。

# 美杜莎

普通大模型只有一个lm_head作为最终的输出，美杜莎给大模型改造多出5个lm_head，分别预测t+1,t+2,t+3,t+4,t+5，由于不同头之间信息不透明，
所以前面几个头保留的token多一点，比如t+1保留三个,t+2保留两天，2*3=6的tree attn验证。

# MTP
<img width="1440" height="795" alt="image" src="https://github.com/user-attachments/assets/31d9d558-0bee-4096-b8b6-72fca16d6648" />
MTP推理很简单，前一层的hidden_state + embd(预测token)，先RMS再linear[2*h,h]再过一个block，最后lm_head。

这里的 $embd_{main}$ = $embd_{MTP}$, $lmhead_{main}$ = $lmhead_{MTP}$，是同一个。

重点是训练：
<img width="896" height="100" alt="image" src="https://github.com/user-attachments/assets/a5050d35-e727-4fb9-892f-fa1841ad29ee" />
MTP公式是这样的，总的LOSS是 $L_{MAIN}$ + 0.3 * $L_{MTP}$，在loss对ce+softma+求导的时候，两个loss分别求出p-y，然后再加起来接着正常往下走。
注意，main和MTP的loss对main有梯度，但是main的loss对MTP模块没有梯度。

因为MTP对让第x个位置能够瞻前顾后，所以对训练效果有提升。


# dflash

eagle没有消除串行，只不过把大模型的串行放到了小模型的串行。

<img width="650" height="390" alt="image" src="https://github.com/user-attachments/assets/bd74b9aa-3f71-45a6-b114-ad241b8f801d" />

总之就是想办法降低draft模型时间，或者接受token数量。

dflash从倒数第二层和倒数第三层均匀抽出五层hidden states并乘自己权重，组成新的状态target feature $H_t$

五个创新点：
## KV Injection
<img width="1006" height="610" alt="image" src="https://github.com/user-attachments/assets/18cd7ab7-9adc-4a46-8d54-501f865f93d2" />

把target hidden state变成一段persistent prefix kv，这样让模型更加记得target info。

解释一下这里的流程：假如说上下文有A B C三个token，dim=2048，这一次有decode/prefill的一个anchor token是D。
block=4的话[D,<mask>,<mask>,<mask>]后三个都是mask这个相同token，有相同的emb。

在prefill/decode的时候会把A B C三者的某几层hidden_state(这里假设是6,具体几层会写到模型config):hybird_hidden_state=[3,2048 * 6],注意这里没有D，因为D还没有hidden_state而且是block内部。

hybird_hidden_state=[3,2048 * 6] @ [2048*6,2048] = context_state [3,2048],context_state @ Wkv_layer_i [2048,2048] = [3,2048]得到某一层的KV

然后正常进行attention。

## Block Diffusion Parallel
采用diffusion的方式，mask的token双向可见，一次forward预测16个token，一次forward全部给出。

training的时候把Target model完全冻结只训练draft layers。

## Random Masked Blocks & Early Token Loss权重大
普通的block diffusion指死活固定切response，但是这和真实的inference肯定不一致。

训练的时候随机mask block来预测。

并且因为投机解码前面的token最重要，所以损失函数CE多了一个权重，前面的权重最大

# dspark
<img width="1280" height="616" alt="image" src="https://github.com/user-attachments/assets/ed306b49-f709-460d-b033-685fb78f5efb" />

和dflash的公式一样，dsprk也是同样的目的，从这个公式角度入手。

首先是降低T_draft：采用dflash的并行调用降低耗时，而不是AR，这样一次forward就能得到五个token。

dpsk团队观察到了：dflash到了后面的token P(accept | x_i-1全accept)的概率原来越低，而eagle-3越来越高，这是AR特性决定的，考虑到了前后依赖，dflahs没有考虑到。就是dflahs前面的token准，后面的token不准，延迟低；eagle-3前面的token不准，后面的token准，延迟高。

比如：Sure, [of/no] [course,problem] 分开来看每一个都合理，但是组合起来不能是of problem，这就是dflahs的问题 没有考虑到draft token之间的组合。

为了让接受率/接受长度上升，dpsk团队采用了一个马尔可夫链在每一个draft token增加了sequential stage(Markov Head)：p_d @ [vocab,256] @ [256,vocab] 这两个lowrank矩阵来保证延迟同时注意前一个token的联系，提升成功率。（这里dpsk也采用了RNN考虑前面所有token的联系 但是效果一般，延迟上涨了很多）。这里的sequntial head值增加了约1%延迟。

通过这种 半自回归的形式，接受长度和T_draft都能有收获。那怎么让T_verify降低呢？这里dpsk的方案是减少验证token。


具体方案是这样的：首先提出了一个概念叫做confidence head，指的是：

在前面token全部接受的前提下，当前token的接受概率。在此基础上 前缀乘积我们就可以得到前面token全部的接受概率了。


<img width="1736" height="1650" alt="image" src="https://github.com/user-attachments/assets/8788e994-d5fb-478b-90ea-a5cdbd0621ac" />
在此基础上我们引入SPS(B)，指的是 veriy B个token的情况下 一秒钟能forward SPS(B)次。(B从request个数开始增加，prefill肯定增加一个token)
那Θ=τ⋅SPS(B)​公式其实就很明确了，τ的意思是这个verify的置信度 其实就是数学期望。Θ的意思其实就是一秒钟能verify多少token的吞吐。

在最新的sglang代码里面 SPS变成了两维：SPS(batch,verify toekns)

先把c从高到低排序，然后按照置信度来verify。
比如R=3,B=R+1=4,SPS= R1_a1=0.9,Θ=0.9 * 100
B=R+2=5,SPS=97,R1_a2=0.85,Θ=(0.9+0.85) * 97，直到Θ吞吐下降，就不再增加verify。

这个视角就是降低T_target。
